# On a Cut 刷脂助手 — 需求与功能说明

本文件是项目的唯一上下文来源。改功能前先读，改完后更新对应小节和文末的变更记录。

## 1. 定位

- 面向任何成年用户的减脂 / 维持 / 增肌饮食与训练记录工具，手机上使用，可长期使用。
- 纯前端单页，无后端、零依赖（原生 JS）；可直接部署到 GitHub Pages，每个访问者的数据只在自己的浏览器里。
- 核心理念：用“掌、拳、勺、茶匙”等实物单位记录；不极端节食；甜点可以吃，用对冲机制消化。
- 项目发起人（仓库所有者）的个人设定见第 8 节，作为旧数据迁移和默认口味的依据。

## 2. 计算引擎（`src/engine.js` 的 `compute`）

输入：性别、年龄、身高、当前体重、目标体重（可空）、每周训练次数 0–7、目标模式。

- 基础代谢 BMR（Mifflin-St Jeor）：`10·体重 + 6.25·身高 − 5·年龄 + 5（男）/ −161（女）`。
- 日常总消耗 TDEE = BMR × 活动系数。每周训练 0–7 次对应 `1.2, 1.3, 1.375, 1.45, 1.5, 1.6, 1.675, 1.75`。
- 目标模式：

| 模式 | 热量 | 蛋白 g/kg | 脂肪 g/kg |
| --- | --- | --- | --- |
| 温和刷脂 `cut1` | TDEE −15% | 1.7 | 0.75 |
| 激进刷脂 `cut2` | TDEE −25% | 2.0 | 0.7 |
| 维持 `keep` | TDEE | 1.4 | 0.9 |
| 增肌 `bulk` | TDEE +10% | 1.8 | 0.9 |

- 安全下限：日均热量不低于 1200（女）/ 1500（男）kcal，触发时在结果里说明。
- BMI 超过 27 时，蛋白和脂肪按 BMI 27 对应的体重计算。
- 碳水 = 剩余热量 ÷ 4，最低 50g。
- 训练日比休息日多约 140 kcal（约 1 拳主食），周均热量不变；每周 0 或 7 练时不区分。
- 目标存成区间：蛋白 ±5、碳水 ±8、脂肪 ±3、热量 ±50；蛋白底线 = 目标的 80%。
- 预计每周变化 = 日均缺口 × 7 ÷ 7700；有目标体重时给出预计周数。
- 目标体重低于 BMI 18.5 时给出提醒；年龄限 18–90。
- “手动设置目标”（`profile.custom`）开启后不再自动计算，直接编辑 16 个区间数值。

## 3. 界面原则

- 数字和卡片优先，文字越少越好；大段说明放进“准则”页折叠。
- 首屏先回答“今天还能吃多少”（剩余热量大数字），再看三大营养素。
- 一次点按完成记录；吃过的东西能重复点选，不重复调用模型；前一天吃的可整天复制。
- 评价和建议要短，一行以内，直接说怎么做。
- 改动数据的危险操作（恢复备份）需要二次点按确认。

## 4. 功能模块

底部四个标签：今天 / 对冲 / 记录 / 准则。每页右上角有人像按钮，打开“身体档案与设置”。

### 首次引导（`openSheet("onb")`）
本地没有档案时自动弹出，四步：性别 / 年龄 / 身高 → 当前体重 / 目标体重 / 模式 → 每周训练次数 / 进食时间（不限时、16+8、14+10）→ 展示计算结果。完成后写入档案、目标、每周安排，周期起始日为当天。

### 身体档案与设置（`openSheet("prof")`）
身体数据、模式、训练次数（实时预览目标）、手动目标开关、进食窗口时间、每周默认安排、数据备份。点“保存”才生效。

### 今天（`viewToday`）
- 日期切换（可回看，可提前排 7 天）；状态切换（训练日 / 休息日）。
- 剩余热量大数字 + 蛋白 / 碳水 / 脂肪三条卷尺进度条（带目标区间和蛋白底线）；启用限时进食时显示窗口倒计时。
- “下一餐怎么吃”卡片（`adviceCard`，数据来自 `advise`，见下方“实时建议”）：三条进度条下方。还没有记录时是一行引导（照参考餐单填入）；有记录后是三张数字卡片 主食 N 拳 / 蛋白 N 掌（或 ✓ 已到位、已超 Xg）/ 油脂（坚果 1 小把 + N 茶匙油，或 0），下面 1–2 行结论。今天的标题是“下一餐怎么吃”，今天还剩 2 餐以上时附“· 还有 N 餐，每餐约一半”；其他日期的标题是“这一天还缺”。份量全为 0 时不显示卡片，只写“今天已经吃到位了 ✓”。
- 参考餐单（`buildTpl` / `tplCard`）：按当天目标自动算出掌、拳、茶匙份数和用餐时间。当天没有记录时可一键填入；已有记录时折叠、只展示，不提供按钮。
- 记一口：餐次（只在看今天时按时间自动选中，其他日期默认第 1 餐）+ 食物类别（常吃、蛋白质、主食、蔬果、油脂、甜点），点一下记 1 份。每个分类只显示食物库里标了 `top` 的 8–12 个默认格子，末尾一行灰字“更多食物下一版可搜索”（v7 的临时占位，搜索入口在批次 2B 加）。
- 自定义食物：输入描述由 Claude 估算（仅 Artifact 内），或手动填克数 / 只填热量；记录后自动存入“常吃”。可勾选“算甜点（对冲页可选）”，估算时由模型预填。
- 当天记录：按餐次分组，±半份，每餐一行规则评价（`mealNote`）；空白时可“整天复制前一天”；有记录时标题右侧有“清空”（只清饮食条目，不动体重、训练和喝水，不二次确认，靠撤销兜底）。
- 跨午夜（`rollDay`）：回到前台或每 30 秒检查一次，日期变了且正停在“旧的今天”，自动跳到新的今天。
- 喝水：250ml 一杯，目标 8 杯。

### 对冲（`viewHedge`）
点甜点预演：把甜点加到当天已吃上，再调用同一个 `advise`（按只剩 1 餐算）。显示和今天页相同的三张卡片 主食 / 蛋白 / 油脂；结论区是几枚 pill：是否仍在额度内（超出 60 kcal 以上时写“接下来 N 天每天少半拳主食”）、蔬菜两捧、不加练明早照常；最后是碳水 / 脂肪 / 热量的剩余额度。甜点选项 = 食物库里全部 `cat="sweet"` 的食物（不受 `top` 限制，含奶茶、可乐、酒、薯片等零食饮品）+ “常吃”里标了甜点（`s=1`）的食物。

### 实时建议（`advise`）
输入当天已吃、当天目标、今天还剩几餐、窗口是否已关、是否有只填了热量的条目；输出主食拳数、瘦肉掌数、坚果和油的份数、吃完后的预计合计、超出热量和摊平天数。

分配顺序和理由：
1. **蛋白下限**：差多少补多少掌瘦肉（差 8g 以内不补）。蛋白决定保不保得住肌肉，最优先；已超上限就不再安排肉。
2. **蔬菜两捧**：固定留出 44 kcal。
3. **脂肪下限**：补到下限为止，但最多占剩余额度的一半。脂肪长期过低影响激素，所以排在碳水前面；封顶一半是为了不让油把主食挤光。满 13g 用 1 小把坚果，其余用油（整茶匙）。
4. **碳水**：剩下的额度全部给主食，同时不超过碳水上限。

其他规则：剩余热量一律按热量区间的中点算；额度不够时主食和油归零、蛋白照保，超出上限 60 kcal 以上的部分按每天 80 kcal（约半拳主食）摊到之后 2–5 天；窗口已关时只在蛋白低于底线时建议 1 勺蛋白粉，否则到此为止；有条目只填了热量时提示“仅供参考”。

### 撤销
- 通用撤销提示条（`withUndo`）：操作前给这一天（或“常吃”列表）拍快照，提示条上带“撤销”按钮，显示 5 秒，只保留最近一次。适用于：减到 0 删除条目、整天复制、填入参考餐单、对冲页记入、删除常吃、清空这一天。
- 撤销恢复备份：恢复前把当前全部数据存进 `onacut.v1.undo`；设置抽屉的“数据备份”里出现“撤销上次恢复（时间）”，二次点按确认后回到恢复前。存不下时提示“空间不足，这次恢复无法撤销”，仍可恢复。

### 记录（`viewLog`）
本周训练打卡与笔记；本周饮食（日均热量、日均蛋白、蛋白达标天数，蛋白 ≥ 下限算达标）；晨起体重 / 腰围、7 日均重、目标进度条、速度判断（按模式不同）、趋势图；体重偏离档案 ≥1 kg 时提示一键重新计算目标；最近 30 天打卡格（深色 = `dayOk`：蛋白 ≥ 下限且热量 ≤ 上限，不留余量）。

### 准则（`viewGuide`）
按当前目标生成的额度表和实物换算、饮食规则、对冲规则、训练要点、计量表、调整规则；“复制 AI 交接档案”。

## 5. 数据与存储

- `localStorage["onacut.v1"]` = `{settings, days}`；另有 `onacut.v1.tab`（上次标签）、`onacut.v1.bk`（上次导出时间）、`onacut.v1.undo`（恢复备份前的快照 `{at, data:{settings, days}}`，撤销后删除）。键名不能改。
- `settings`：`profile{sex,age,h,w,goal,n,mode,custom,done}, t{train,rest}{p,pf,c,f,k}, plan[7], states[], fast, win{A,B,C}, start, weight0, my[], updatedAt`。`my[]` 里的常吃条目：`{id, cat:"my", n, p, c, f, k?, s?}`，`s=1` 表示算甜点；旧条目没有 `s`，按 0 处理。
- 每天：`state, entries[], water, lift, cardio, note, weight, waist, updatedAt`。
- 条目：`{id, fid?, n, q, p, c, f, k?, m(1–4), s}`；营养值在记录时拷贝，`k` 存在时热量取 `k`。`fid` 可能是内置食物的基准 id（`rice`）、份量变体 id（`rice@bowl`）或自定义食物 id（`my-…`）；判断“是不是某种食物”一律先过 `baseId()`。
- 状态键：`A` 训练日、`C` 休息日；旧数据另有 `B`（见第 8 节）。
- 备份：导出为 JSON。独立网页直接下载文件；Artifact 内不能下载，改为复制文本。恢复支持选文件或粘贴文本，二次确认后整体覆盖；原来有、备份里没有的日期会写成带新时间戳的空白日，这样云端的旧数据不会被拉回来。数据满 7 天且 14 天未导出时，人像按钮显示提醒点（云端同步时不提醒）。
- 迁移（`migrate`）：有旧数据但没有 `profile` 时，自动建立手动目标档案并保留三种状态，不弹引导。
- 云端（仅 Artifact 内，附加能力）：`db` 能力，`data/users/<用户id>/`，按 `updatedAt` 新者覆盖。

### 食物库（`src/foods.js`，v7）

导出 `{FOODS, GROUPS, TAGS, CATS}`，只有数据。共 184 种，营养值都是按常见份量估算的。每种食物：

```
{ id:"rice",            // 小写字母数字，唯一。v6 的 30 个旧 id 不能改，p/c/f 也不能改
  cat:"carb",           // 营养分类 pro / carb / veg / fat / sweet，决定出现在哪个分类标签；sweet 的条目记录时 s=1、出现在对冲页
  g:"home",             // 场景分组 home 家常 / west 西式轻食 / out 外卖外食 / snack 零食饮品 / sweet 甜点，搜索结果里的小标签
  n:"米饭/杂粮饭",       // 纯名称，不含份量
  a:["白饭","大米饭"],   // 别名，可为空
  py:"mfzlf",           // 名称里每个汉字的拼音首字母 + 英文字母，全小写；长度必须等于汉字数 + 字母数（测试会查）
  u:[{k:"fist",l:"1 拳",x:1},{k:"bowl",l:"1 碗",x:1.5},{k:"g100",l:"100g",x:0.87}],
                        // 份量。第一个是基准（x 必须为 1）；k 小写字母数字，同一食物内唯一
  p:3, c:33, f:0.5,     // 基准份量的蛋白 / 碳水 / 脂肪（g），保留到 0.5
  k:…,                  // 可选：基准份量热量。外卖外食、含酒精饮品必填；与 4p+4c+9f 相差不超过 15%（含酒精的除外）
  top:1,                // 可选：出现在分类标签的默认格子里（每个 cat 8–12 个）
  tags:["gluten"] }
```

- **显示名** = `n + " " + u[0].l`（如“米饭/杂粮饭 1 拳”）。旧食物拆分后拼回去与 v6 的显示名完全一致。
- **份量变体 id** = `<基准 id>@<份量 k>`（如 `rice@bowl`）。变体的显示名 = `n + " " + l`，p/c/f/k 乘以 `x` 后保留 1 位小数；基准没有 `k` 的，变体也没有 `k`。
- **TAGS**（饮食标签，本版只标注、不过滤，留给“饮食偏好”批次）：`meat` 任何畜禽肉（不含鱼和海鲜）、`pork` 猪肉、`beef` 牛肉、`poultry` 禽肉、`fish` 鱼、`seafood` 虾蟹贝等海鲜、`egg` 蛋、`dairy` 奶制品、`whey` 乳清蛋白、`soy` 大豆制品、`gluten` 含麸质、`nut` 坚果和花生、`alcohol` 含酒精。带 `pork / beef / poultry` 的必须同时带 `meat`。
- 加食物时：先定 id 和基准份量，写 py，填 tags；外卖必须带 `k`；跑测试会检查以上所有规则。

### 引擎里的食物表和查找函数（`src/engine.js`，供批次 2B 调用）

- `FOODS`：只含基准份量，`{id, cat, n:显示名, p, c, f, k?, top?, g, tags, base:foods.js 里的原始对象}`。
- `FBY[id]`：基准对象（就是 `FOODS` 里的那个）加上全部变体；变体形状 `{id:"rice@bowl", cat, n, p, c, f, k?, g, tags, baseOf:"rice"}`。
- `baseId(fid)`：去掉 `@` 之后的部分；`undefined` 返回 `""`。
- `portionsOf(id)`：某个基准 id 的全部份量（FBY 对象数组，基准在前）；id 不存在或传入变体 id 时返回 `[]`。
- `guessCat(f)`：给自定义食物猜分类。`s` 为真 → `sweet`；三大营养素都为 0 → `carb`；蛋白热量占比 ≥ 40% → `pro`；脂肪热量占比 ≥ 50% → `fat`；其余 `carb`。不会猜出 `veg`。
- `searchFoods(q, {my, fav, recent, limit=8})` → `[{food, score}]`。`q` 去空格转小写，空串返回 `[]`。候选是内置基准食物和 `my`（自定义食物，只按名称）。基础分取最高一项：名称相等 100、名称以 q 开头 80、别名相等 75、名称包含 60、别名包含 50；q 全是英文字母时，拼音首字母以 q 开头 45、包含 30（q 只有 1 个字母时只认开头）。自定义食物用名称里的英文字母当拼音首字母。加分：`recent`（`{fid: 次数}`，按 `baseId` 合并）每次 +3、最多 +15；在 `fav`（基准 id 或自定义 id 的数组）里 +8；自定义食物 +5。按分数降序，同分名称短的在前。`food` 对内置食物是 `FOODS` 里的对象，对自定义食物是传入的原对象。
- `recentFoods(days, todayStr, n=8)` → 快照数组 `{id, n, p, c, f, k?, s, cat:"recent"}`。统计 `todayStr` 之前 14 天（不含当天）的条目，按 `fid` 分组（没有 `fid` 的按名称，id 记为 `"rc-"+名称`），数值取每组最近一次的条目本身、不回查食物库，所以已删除的自定义食物也会出现。按出现次数降序、最近日期降序。

## 6. 工程结构与平台限制

- `src/foods.js`：食物库数据（见第 5 节“食物库”），没有逻辑。浏览器里是 `self.OnACutFoods`，Node 里是 `module.exports`。文件里不能出现 `</script>`。必须先于 engine.js 加载。
- `src/engine.js`：计算引擎，全部是纯函数和常量（`compute`、`pfError`、`buildTpl`、`advise`、`dayOk`、`totals`、`mealNote`、食物表与查找函数、日期工具），不碰 DOM 和存储。开头从 `OnACutFoods`（Node 下 `require("./foods.js")`）取数据，取不到就抛错。浏览器里是 `window.OnACutEngine`，Node 里是 `module.exports`。文件里不能出现 `</script>`。
- `src/on-a-cut.html`：页面主体（样式、存储与同步、视图、事件）。主脚本前有一行 `<!--ENGINE-->` 占位符，开头从 `OnACutEngine` 解构所需函数。
- `sh build.sh`（无参数）：把 foods.js 和 engine.js（foods 在前，同一个 `<script>`）内联到占位符处 → `dist/page.html`（发布 Artifact 用）；再套上外壳 → `index.html`（GitHub Pages 用）。两个产物都提交进仓库，都不手改。
- 测试：`node --test tests/`，提交前必须通过。`tests/engine.test.js` 覆盖 compute、pfError、日期运算、buildTpl、advise（示例 + 500 组随机输入的不变量），以及 searchFoods、recentFoods、portionsOf、guessCat、baseId；`tests/foods.test.js` 校验食物库的结构、旧 id 与 v6 数值一致、份量变体、各分组数量。入口是 `tests/run-all.js`（`tests/package.json` 的 `main` 指向它，Node 22 靠这个找到测试）；新增测试文件要在 `run-all.js` 里登记，入口文件名不要带 `.test.`，否则会扫描目录的新版 Node 会把用例跑两遍。
- 写入 `settings` 或某一天的数据必须经过 `touch()`；营养值在记录时拷贝进条目。


- Artifact 内没有 `confirm/alert`、不能下载文件。
- “估算”依赖 `sample` 能力，只在 Artifact 链接里可用；GitHub Pages 上退回手动填写。
- 食物库营养值均为估算值；计算结果是一般性健康建议，页面内有免责声明。
