# On a Cut 刷脂助手 — 需求与功能说明

本文件是项目的唯一上下文来源。改功能前先读，改完后更新对应小节和文末的变更记录。

## 1. 定位

- 面向任何成年用户的减脂 / 维持 / 增肌饮食与训练记录工具，手机上使用，可长期使用。
- 纯前端单文件，无后端；可直接部署到 GitHub Pages，每个访问者的数据只在自己的浏览器里。
- 核心理念：用“掌、拳、勺、茶匙”等实物单位记录；不极端节食；甜点可以吃，用对冲机制消化。
- 项目发起人（仓库所有者）的个人设定见第 8 节，作为旧数据迁移和默认口味的依据。

## 2. 计算引擎（`compute`）

输入：性别、年龄、身高、当前体重、目标体重（可空）、每周训练次数 0–7、目标模式。

- 基础代谢 BMR（Mifflin-St Jeor）：`10·体重 + 6.25·身高 − 5·年龄 + 5（男）/ −161（女）`。
- 日常总消耗 TDEE = BMR × 活动系数。每周训练 0–7 次对应 `1.2, 1.3, 1.375, 1.45, 1.5, 1.6, 1.675, 1.75`。
- 目标模式：

| 模式 | 热量 | 蛋白 g/kg | 脂肪 g/kg |
| --- | --- | --- | --- |
| 温和刷脂 `cut1` | TDEE −15% | 1.7 | 0.75 |
| 激进刷脂 `cut2` | TDEE −25% | 2.0 | 0.7 |
| 维持 `keep` | TDEE | 1.4 | 0.9 |
| 增肌 `bulk` | TDEE +10% | 1.8 | 0.9 |

- 安全下限：日均热量不低于 1200（女）/ 1500（男）kcal，触发时在结果里说明。
- BMI 超过 27 时，蛋白和脂肪按 BMI 27 对应的体重计算。
- 碳水 = 剩余热量 ÷ 4，最低 50g。
- 训练日比休息日多约 140 kcal（约 1 拳主食），周均热量不变；每周 0 或 7 练时不区分。
- 目标存成区间：蛋白 ±5、碳水 ±8、脂肪 ±3、热量 ±50；蛋白底线 = 目标的 80%。
- 预计每周变化 = 日均缺口 × 7 ÷ 7700；有目标体重时给出预计周数。
- 目标体重低于 BMI 18.5 时给出提醒；年龄限 18–90。
- “手动设置目标”（`profile.custom`）开启后不再自动计算，直接编辑 16 个区间数值。

## 3. 界面原则

- 数字和卡片优先，文字越少越好；大段说明放进“准则”页折叠。
- 首屏先回答“今天还能吃多少”（剩余热量大数字），再看三大营养素。
- 一次点按完成记录；吃过的东西能重复点选，不重复调用模型；前一天吃的可整天复制。
- 评价和建议要短，一行以内，直接说怎么做。
- 改动数据的危险操作（恢复备份）需要二次点按确认。

## 4. 功能模块

底部四个标签：今天 / 对冲 / 记录 / 准则。每页右上角有人像按钮，打开“身体档案与设置”。

### 首次引导（`openSheet("onb")`）
本地没有档案时自动弹出，四步：性别 / 年龄 / 身高 → 当前体重 / 目标体重 / 模式 → 每周训练次数 / 进食时间（不限时、16+8、14+10）→ 展示计算结果。完成后写入档案、目标、每周安排，周期起始日为当天。

### 身体档案与设置（`openSheet("prof")`）
身体数据、模式、训练次数（实时预览目标）、手动目标开关、进食窗口时间、每周默认安排、数据备份。点“保存”才生效。

### 今天（`viewToday`）
- 日期切换（可回看，可提前排 7 天）；状态切换（训练日 / 休息日）。
- 剩余热量大数字 + 蛋白 / 碳水 / 脂肪三条卷尺进度条（带目标区间和蛋白底线）；启用限时进食时显示窗口倒计时。
- 下一步提示（`nextHint`）：还差几掌肉、还能吃几拳主食。
- 参考餐单（`buildTpl` / `tplCard`）：按当天目标自动算出掌、拳、茶匙份数和用餐时间，可一键填入；已有记录时折叠。
- 记一口：餐次（打开时按时间自动选中）+ 食物类别（常吃、蛋白质、主食、蔬果、油脂、甜点），点一下记 1 份。
- 自定义食物：输入描述由 Claude 估算（仅 Artifact 内），或手动填克数 / 只填热量；记录后自动存入“常吃”。
- 当天记录：按餐次分组，±半份，每餐一行规则评价（`mealNote`）；空白时可“整天复制前一天”。
- 喝水：250ml 一杯，目标 8 杯。

### 对冲（`viewHedge` / `hedgePlan`）
点甜点预演 → 三张数字卡片（主食几拳、蛋白几掌、蔬菜两捧）+ 一行结论 + 剩余额度。

### 记录（`viewLog`）
本周训练打卡与笔记；本周饮食（日均热量、日均蛋白、蛋白达标天数）；晨起体重 / 腰围、7 日均重、目标进度条、速度判断（按模式不同）、趋势图；体重偏离档案 ≥1 kg 时提示一键重新计算目标；最近 30 天打卡格。

### 准则（`viewGuide`）
按当前目标生成的额度表和实物换算、饮食规则、对冲规则、训练要点、计量表、调整规则；“复制 AI 交接档案”。

## 5. 数据与存储

- `localStorage["onacut.v1"]` = `{settings, days}`；另有 `onacut.v1.tab`（上次标签）、`onacut.v1.bk`（上次导出时间）。
- `settings`：`profile{sex,age,h,w,goal,n,mode,custom,done}, t{train,rest}{p,pf,c,f,k}, plan[7], states[], fast, win{A,B,C}, start, weight0, my[], updatedAt`。
- 每天：`state, entries[], water, lift, cardio, note, weight, waist, updatedAt`。
- 条目：`{id, fid?, n, q, p, c, f, k?, m(1–4), s}`；营养值在记录时拷贝，`k` 存在时热量取 `k`。
- 状态键：`A` 训练日、`C` 休息日；旧数据另有 `B`（见第 8 节）。
- 备份：导出为 JSON。独立网页直接下载文件；Artifact 内不能下载，改为复制文本。恢复支持选文件或粘贴文本，二次确认后整体覆盖。数据满 7 天且 14 天未导出时，人像按钮显示提醒点（云端同步时不提醒）。
- 迁移（`migrate`）：有旧数据但没有 `profile` 时，自动建立手动目标档案并保留三种状态，不弹引导。
- 云端（仅 Artifact 内，附加能力）：`db` 能力，`data/users/<用户id>/`，按 `updatedAt` 新者覆盖。

## 6. 平台限制

- Artifact 内没有 `confirm/alert`、不能下载文件。
- “估算”依赖 `sample` 能力，只在 Artifact 链接里可用；GitHub Pages 上退回手动填写。
- 食物库营养值均为估算值；计算结果是一般性健康建议，页面内有免责声明。

## 7. 变更记录

- v1：四个页面、手势计量记录、云端同步。
- v2：对冲页改为数字卡片；描述食物由 Claude 估算。
- v3：参考餐单，可一键填入；可提前排 7 天。
- v4：自定义食物可填热量并存入“常吃”；燕麦默认 20g；每餐一行评价；源码移入 `src/`。
- v5：通用化。Mifflin-St Jeor 计算引擎、首次引导、身体档案抽屉、JSON 备份与恢复；参考餐单按目标自动生成；首屏改为剩余热量；自动选餐次、整天复制前一天、本周饮食统计、目标进度条、体重变化后重新计算、备份提醒；30 天周期改为滚动的最近 30 天。

## 8. 项目发起人的个人设定（旧数据）

- 63.5 kg / 163.5 cm，每周 4 练（40 分钟抗阻 + 40 分钟爬坡）。
- 手动目标：训练日 蛋白 100–110 / 碳水 165–180 / 脂肪 42–48 / 1500–1600 kcal；休息日 蛋白 100–110 / 碳水 125–140 / 脂肪 42–48 / 1350–1450 kcal；蛋白底线 85g。
- 三种状态：A（11 点练完，16+8，11:30–19:30）、B（9 点练完，14+10，09:30–19:30）、C（休息日）。
- 习惯：Bulk 蛋白粉、法棍、燕麦每次 20g；喜欢 Flan、可颂等烘焙甜点。
- 问过“蛋白 1 g/kg + 碳水 2.5 g/kg”，结论是保持现方案。
