# On a Cut 刷脂助手 — 需求与功能说明

本文件是项目的唯一上下文来源。改功能前先读，改完后更新对应小节和文末的变更记录。

## 1. 定位

- 面向任何成年用户的减脂 / 维持 / 增肌饮食与训练记录工具，手机上使用，可长期使用。
- 纯前端单页，无后端、零依赖（原生 JS）；可直接部署到 GitHub Pages，每个访问者的数据只在自己的浏览器里。
- 核心理念：用“掌、拳、勺、茶匙”等实物单位记录；不极端节食；甜点可以吃，用对冲机制消化。
- 项目发起人（仓库所有者）的个人设定见第 8 节，作为旧数据迁移和默认口味的依据。

## 2. 计算引擎（`src/engine.js` 的 `compute`）

输入：性别、年龄、身高、当前体重、目标体重（可空）、每周训练次数 0–7、目标模式。

- 基础代谢 BMR（Mifflin-St Jeor）：`10·体重 + 6.25·身高 − 5·年龄 + 5（男）/ −161（女）`。
- 日常总消耗 TDEE = BMR × 活动系数。每周训练 0–7 次对应 `1.2, 1.3, 1.375, 1.45, 1.5, 1.6, 1.675, 1.75`。
- 目标模式：

| 模式 | 热量 | 蛋白 g/kg | 脂肪 g/kg |
| --- | --- | --- | --- |
| 温和刷脂 `cut1` | TDEE −15% | 1.7 | 0.75 |
| 激进刷脂 `cut2` | TDEE −25% | 2.0 | 0.7 |
| 维持 `keep` | TDEE | 1.4 | 0.9 |
| 增肌 `bulk` | TDEE +10% | 1.8 | 0.9 |

- 安全下限：日均热量不低于 1200（女）/ 1500（男）kcal，触发时在结果里说明。
- BMI 超过 27 时，蛋白和脂肪按 BMI 27 对应的体重计算。
- 碳水 = 剩余热量 ÷ 4，最低 50g。
- 训练日比休息日多约 140 kcal（约 1 拳主食），周均热量不变；每周 0 或 7 练时不区分。
- 目标存成区间：蛋白 ±5、碳水 ±8、脂肪 ±3、热量 ±50；蛋白底线 = 目标的 80%。
- 预计每周变化 = 日均缺口 × 7 ÷ 7700；有目标体重时给出预计周数。
- 目标体重低于 BMI 18.5 时给出提醒；年龄限 18–90。
- “手动设置目标”（`profile.custom`）开启后不再自动计算，直接编辑 16 个区间数值。

## 2.1 超出摊平（`src/engine.js` 的 `carryOver`，v8.1）

某天吃超了，把超出的部分摊到之后几天：这几天的热量和碳水目标自动降低。结果全部实时推算，不存任何按天的字段。

规则：
1. **超出**：某天有记录（`entries.length > 0`），且已吃热量 − **调整后**的上限 `k[1]` ≥ 30 kcal，整个差值（不减 30）记为一笔欠账。不足 30 kcal 不追；没有记录的日子不产生欠账。
2. **不奖励少吃**：吃少了不产生额度，也不抵消欠账。
3. **摊还窗口**：从超出日的第二天开始还，最多 5 天（+1 到 +5），按日历天算，中间没有记录的日子照扣。过期没还完的部分作废（`lost`）。
4. **单日扣减上限** `cutCap` = `floor(min(150, mid(k)×10%, k[0] − 安全下限, 4×(c[0] − 50)))`，最小 0。扣完后热量下限不低于安全下限，碳水下限不低于 50g；原碳水下限 ≤ 50g 的日子不扣。
5. **叠加**：多笔欠账按超出日先后偿还（旧账先还），每天合计不超过 `cutCap`。
6. **只降碳水**：扣 Δ kcal 时，热量区间整体下移 Δ，碳水区间整体下移 `round(Δ/4)` g；蛋白、蛋白底线、脂肪不变。
7. **连锁**：被调整过的日子，判断超出时用调整后的 `k[1]`。
8. 训练日和休息日一视同仁，按日期先后扣。
9. **安全下限**按档案性别：`profile.sex==="m"` 为 1500，其余（女、旧数据性别为空）为 1200。
10. 开关 `settings.spread`（默认 `true`）。关闭后所有地方用原目标，也不再提摊平。

函数（都是纯函数）：
- `floorOf(sex)` → `sex==="m" ? 1500 : 1200`。
- `cutCap(t, floor)` → 规则 4，≥ 0 的整数。
- `shiftT(t, cut)` → 新对象（不改入参）：`k` 两端 −cut，`c` 两端 −`round(cut/4)`，`p`、`pf`、`f` 拷贝。
- `carryOver(days, baseOf, {floor, to, over?})` → `{days, src}`。
  - `days` 即 `S.days`；`baseOf(date)` 返回这一天的**原始**目标（调用方按当天状态选训练日 / 休息日）；`to` 算到哪一天（含）；`over = {date, k}` 表示“假设这一天已吃 k kcal”，用于预演。
  - 起点是所有有记录的日期和 `over.date` 中最早的一天；没有起点返回 `{days:{}, src:{}}`。逐日推进到 `to`，每天：a. 过期欠账移出，余额累加到 `src[超出日].lost`；b. `t0 = baseOf(date)`，按先后偿还，单日合计 ≤ `cutCap(t0)`，记入 `from` 和 `src[超出日].paid`；c. `t = shiftT(t0, cut)`，`cut > 0` 时写 `days[date] = {cut, from:[{d, k}], t}`；d. 已吃热量（`over.date` 取 `over.k`，否则有记录取 `totals(day).k`，否则跳过），`x = round(已吃 − t.k[1])`，`x ≥ 30` 时新建欠账 `{d, left:x, exp:addDays(d,5)}` 和 `src[d] = {over:x, paid:[], lost:0, left:0}`（`paid` 的每一项是 `{d:还款日, k}`）。
  - 结束时没还完的余额写进 `src[超出日].left`（`to` 之后还会继续还）。`to` 要比最后一个可能的超出日晚至少 6 天，过期部分才会结算成 `lost`。
  - 所有 kcal 都是整数；`days` 只含 `cut > 0` 的日期；每笔欠账 `Σpaid + lost + left = over`。

页面接入（`src/on-a-cut.html`）：
- `calcLED()` 在 `render()` 第一行执行，结果存在 `LED`（开关关闭时为 `null`）；`to = max(今天+7, 正在看的日期+6)`。修改历史、切换状态、撤销、恢复备份、云端拉取后都会重绘，摊平随之更新。搜索输入只重画 `#sr`，不重算（它不显示目标）。
- `tgtOf(date)`：有扣减取调整后的目标，否则 `targets(stOf(dayOf(date)))`。`cutOf(date)`：这一天的 `{cut, from, t}` 或 `null`。
- `spreadOf(date, k)`：开关打开时，用 `over:{date, k}` 跑一次 `carryOver`，返回 `src[date]` 或 `null`。今天页和对冲页的摊平说明只用它，**k 取已记录的热量**（对冲页是已记录 + 正在预演的甜点），这样说明和记入后之后几天实际扣的一致。
- `spreadText(s)`：N = `s.paid.length`；每天相同写“接下来 N 天每天少 Y kcal”，不同写“接下来 N 天共少 X kcal（每天 a / b / …）”；`lost > 0` 追加“，另有 L kcal 摊不完，不再追”；N 为 0 写“之后几天已到安全下限，不再追”。

## 3. 界面原则

- 数字和卡片优先，文字越少越好；大段说明放进“准则”页折叠。
- 首屏先回答“今天还能吃多少”（剩余热量大数字），再看三大营养素。
- 一次点按完成记录；吃过的东西能重复点选，不重复调用模型；前一天吃的可整天复制。
- 评价和建议要短，一行以内，直接说怎么做。
- 改动数据的危险操作（恢复备份）需要二次点按确认。

## 4. 功能模块

底部四个标签：今天 / 对冲 / 记录 / 准则。每页右上角有人像按钮，打开“身体档案与设置”。

### 首次引导（`openSheet("onb")`）
本地没有档案时自动弹出，四步：性别 / 年龄 / 身高 → 当前体重 / 目标体重 / 模式 → 每周训练次数 / 进食时间（不限时、16+8、14+10）→ 展示计算结果。完成后写入档案、目标、每周安排，周期起始日为当天。

### 身体档案与设置（`openSheet("prof")`）
身体数据、模式、训练次数（实时预览目标）、手动目标开关、“超出热量自动摊平到之后几天”开关（v8.1，`#dr-spread`，引导里不显示）、进食窗口时间、每周默认安排、数据备份。点“保存”才生效。

### 编辑组合（`openSheet("combo", id)`，v8）
入口：常吃标签的整理模式里点组合的“✎ 编辑”。草稿是独立变量 `cdr`（不用档案草稿 `dr`）。可以改名、每样 ±0.5 或直接输入倍数、删掉其中一样；底部显示合计热量和蛋白。“保存”写回并关闭（名称为空或一样都不剩时在抽屉内报错）；“删除组合”可撤销。

### 我的食物（`openSheet("foods")`，v8）
入口：分类区末尾的“管理我的食物（N）”。顶部按名称过滤；每行显示名称、分类、热量和 ☆ 收藏开关；点名称展开编辑区（名称、分类、蛋白 / 碳水 / 脂肪 / 热量，“保存”“删除”），同时只展开一行。修改立即生效，没有总的保存按钮；删除可撤销，同时移出收藏，历史记录里的条目不受影响。

### 今天（`viewToday`）
- 日期切换（可回看，可提前排 7 天）；状态切换（训练日 / 休息日）。
- 剩余热量大数字 + 蛋白 / 碳水 / 脂肪三条卷尺进度条（带目标区间和蛋白底线）；启用限时进食时显示窗口倒计时。热量、进度条、建议卡片、参考餐单都用**调整后的目标**（`tgtOf`，见 2.1）。
- 摊平说明（v8.1）：这一天有扣减时，热量大数字下方一行“今天 / 预计这一天 / 这一天少 **X kcal**（碳水 −Yg），在摊还 M/D、M/D 超出的部分”。
- “下一餐怎么吃”卡片（`adviceCard`，数据来自 `advise`，见下方“实时建议”）：三条进度条下方。还没有记录时是一行引导（照参考餐单填入）；有记录后是三张数字卡片 主食 N 拳 / 蛋白 N 掌（或 ✓ 已到位、已超 Xg）/ 油脂（坚果 1 小把 + N 茶匙油，或 0），下面 1–2 行结论。今天的标题是“下一餐怎么吃”，今天还剩 2 餐以上时附“· 还有 N 餐，每餐约一半”；其他日期的标题是“这一天还缺”。份量全为 0 时不显示卡片，只写“今天已经吃到位了 ✓”。热量已用完时的结论（v8.1）：按已记录热量预演摊平，有欠账写“超出 **X kcal**，{spreadText}”；没有欠账但照建议吃完会超（`a.overK > 0`）时，开关打开写“超出 X kcal，不到 30 kcal 不用管”（X ≥ 30 时写“吃完预计超出 X kcal，记下后会自动摊到之后几天”），开关关闭写“超出 X kcal”。
- 参考餐单（`buildTpl` / `tplCard`）：按当天目标自动算出掌、拳、茶匙份数和用餐时间。当天没有记录时可一键填入；已有记录时折叠、只展示，不提供按钮。
- 记一口（v8）：从上到下是餐次标签（只在看今天时按时间自动选中，其他日期默认第 1 餐）→ 搜索框 → 搜索结果区 `#sr` / 分类区 `#catarea` / 自定义表单，三者互斥：表单打开时只显示表单；否则搜索框有字显示结果区，没字显示分类区。
  - **搜索**：输入中文、别名或拼音首字母，调用 `searchFoods`（传入我的食物库、收藏、最近 14 天的 fid 次数，最多 8 条）。输入时只重画结果区（`renderSR`），不整页重绘；输入法组字中不搜，`compositionend` 时再搜。每条结果：名称 + 场景分组小标签（自定义食物显示“我的”）+ ☆/★ 收藏按钮；下面是份量按钮（内置食物最多前 4 个份量，自定义食物只有“1 份”），点一下记 1 份并清空搜索框。末尾是“都不是？AI 估算 / 手动填”（AI 估算只在 Artifact 内出现）；没结果时显示“没找到「xxx」”和同样的按钮。回车：有结果时只收起键盘，没结果时走 AI 估算，没有 AI 就打开手动填。
  - **分类区**标签：最近（最近 14 天吃过的，`recentFoods` 前 8 个，有内容才显示）→ 常吃（有收藏或组合才显示）→ 蛋白质 / 主食 / 蔬果 / 油脂 / 甜点。默认选“最近”，没有就选“蛋白质”。五个分类先显示食物库里标了 `top` 的格子，再显示我的食物库里同分类的自定义食物（最多 12 个，带“我的”小标）。末尾一行：“更多食物请在上方搜索 · 手动填 · 管理我的食物（N）”。
  - **三个概念**：*我的食物库*（`settings.my`）= 手动填或 AI 估算过的食物，全部自动保存，能搜到，按分类出现在对应标签里；*常吃*（`settings.fav`）= 用户手动 ☆ 收藏的食物，内置和自定义都可以；*最近* = 自动统计。
  - **常吃标签**：组合在前，收藏的食物在后（按收藏顺序，找不到的跳过）。“整理常吃”模式下，食物格子点 ✕ 是取消收藏（不删除食物本身），组合格子有“✕ 删除”和“✎ 编辑”。
  - **组合**（`settings.combos`）：当天记录里某一餐有 2 条以上时，条目下方出现“存为组合”，起名后把这一餐存下来；之后在“常吃”里点一下，整组记入当前选中的餐次（可撤销）。还没有组合时，“最近”和“常吃”标签末尾有一行引导文字。
- 自定义食物表单（手动填 / AI 估算结果）：名称、分类（必选，五选一；选“甜点”即算甜点、出现在对冲页）、蛋白 / 碳水 / 脂肪 / 热量（可只填热量）、“加入常吃”勾选框。点“记录”后按名称存入或更新我的食物库，并记 1 份；错误提示显示在表单内。AI 估算（仅 Artifact 内）由模型返回名称、克数和分类并预填表单。
- 当天记录：按餐次分组，每餐一行规则评价（`mealNote`）。
  - 每餐标题是“第 N 餐 · HH:MM”，时间取这一餐条目里最小的 `t`，没有时显示“＋时间”；点时间可以改，改后这一餐所有条目的 `t` 一起变，清空则全部删除。任何日期都能改。
  - 条目右侧 − / + 每次半份；点中间的 `×1` 可以直接输入倍数（0.1–20，回车或失焦保存；空值、非数字或 ≤0 放弃）。输入框失焦时整页重绘，这一次点到别处的点击可能不生效（已知限制）。
  - 空白时可“整天复制前一天”；有记录时标题右侧有“清空”（只清饮食条目，不动体重、训练和喝水，不二次确认，靠撤销兜底）。
- 跨午夜（`rollDay`）：回到前台或每 30 秒检查一次，日期变了且正停在“旧的今天”，自动跳到新的今天。
- 喝水：250ml 一杯，目标 8 杯。

### 对冲（`viewHedge`）
点甜点预演：把甜点加到当天已吃上，再调用同一个 `advise`（按只剩 1 餐算，目标用 `tgtOf(cur)`）。显示和今天页相同的三张卡片 主食 / 蛋白 / 油脂；结论区是几枚 pill：是否仍在额度内（v8.1：按已记录 + 预演甜点的热量预演摊平，有欠账时 warn“仍超 X kcal → {spreadText}”；否则照建议吃完会超时，开关打开写“略超 X kcal，不用管”（X ≥ 30 时 warn“吃完预计超 X kcal → 记下后自动摊到之后几天”），开关关闭 warn“仍超 X kcal”；否则“吃完全天仍在额度内”）、蔬菜两捧、不加练明早照常；最后是碳水 / 脂肪 / 热量的剩余额度。甜点选项 = 食物库里全部 `cat="sweet"` 的食物（不受 `top` 限制，含奶茶、可乐、酒、薯片等零食饮品）+ 我的食物库里分类为甜点的食物。“吃了，记入”记到加餐，按实时记录处理（见第 5 节条目的 `t`）。

### 实时建议（`advise`）
输入当天已吃、当天目标、今天还剩几餐、窗口是否已关、是否有只填了热量的条目；输出主食拳数、瘦肉掌数、坚果和油的份数、吃完后的预计合计、超出热量和摊平天数。**`spreadDays` 已弃用（v8.1）**：字段保留（测试有断言），页面不再使用，摊平改由 `carryOver` 实现（见 2.1）。

分配顺序和理由：
1. **蛋白下限**：差多少补多少掌瘦肉（差 8g 以内不补）。蛋白决定保不保得住肌肉，最优先；已超上限就不再安排肉。
2. **蔬菜两捧**：固定留出 44 kcal。
3. **脂肪下限**：补到下限为止，但最多占剩余额度的一半。脂肪长期过低影响激素，所以排在碳水前面；封顶一半是为了不让油把主食挤光。满 13g 用 1 小把坚果，其余用油（整茶匙）。
4. **碳水**：剩下的额度全部给主食，同时不超过碳水上限。

其他规则：剩余热量一律按热量区间的中点算；额度不够时主食和油归零、蛋白照保，超出上限 60 kcal 以上时给出 `spreadDays`（已弃用，页面改用 2.1 的 `carryOver`）；窗口已关时只在蛋白低于底线时建议 1 勺蛋白粉，否则到此为止；有条目只填了热量时提示“仅供参考”。

### 撤销
- 通用撤销提示条（`withUndo`）：操作前给这一天拍快照（key 为 `"settings"` 时快照是 `{my, fav, combos}` 三者，撤销时一起写回），提示条上带“撤销”按钮，显示 5 秒，只保留最近一次。适用于：减到 0 删除条目、整天复制、填入参考餐单、对冲页记入、记入组合、清空这一天、整理常吃里取消收藏、删除组合、删除我的食物。搜索结果和我的食物抽屉里点 ☆ 是开关，不走撤销。
- 撤销恢复备份：恢复前把当前全部数据存进 `onacut.v1.undo`；设置抽屉的“数据备份”里出现“撤销上次恢复（时间）”，二次点按确认后回到恢复前。存不下时提示“空间不足，这次恢复无法撤销”，仍可恢复。

### 记录（`viewLog`）
本周训练打卡与笔记；本周饮食（日均热量、日均蛋白、蛋白达标天数，蛋白 ≥ 下限算达标）；晨起体重 / 腰围、7 日均重、目标进度条、速度判断（按模式不同）、趋势图；体重偏离档案 ≥1 kg 时提示一键重新计算目标；最近 30 天打卡格（深色 = `dayOk`：蛋白 ≥ 下限且热量 ≤ 上限，不留余量；v8.1 起上限用调整后的目标 `tgtOf`）。本周“蛋白达标天数”只看蛋白，仍用原目标。

### 准则（`viewGuide`）
按当前目标生成的额度表和实物换算、饮食规则、对冲规则、训练要点、计量表、调整规则；“复制 AI 交接档案”。额度表、设置抽屉、引导、体重变化后重新计算、AI 交接档案都用**原目标**，不受摊平影响。对冲规则和调整规则里写明了摊平规则（v8.1）。

## 5. 数据与存储

- `localStorage["onacut.v1"]` = `{settings, days}`；另有 `onacut.v1.tab`（上次标签）、`onacut.v1.bk`（上次导出时间）、`onacut.v1.undo`（恢复备份前的快照 `{at, data:{settings, days}}`，撤销后删除）。键名不能改。
- `settings`：`profile{sex,age,h,w,goal,n,mode,custom,done}, t{train,rest}{p,pf,c,f,k}, plan[7], states[], fast, win{A,B,C}, start, weight0, my[], fav[], combos[], spread, updatedAt`。`my[], fav[], combos[]` 见下。
  - `spread`（v8.1，布尔，默认 `true`）：超出热量自动摊平的开关，见 2.1。`migrate()` 里不是布尔值时设为 `true`（旧数据、旧备份恢复后都是开）。摊平结果不落盘，没有任何按天的新字段。
  - `my[]`（我的食物库，v8）：`{id:"my-…", n, p, c, f, k?, cat:"pro|carb|veg|fat|sweet", s}`，`s = cat==="sweet" ? 1 : 0`。新的在最前；上限 300，超出时从最旧的往前找第一个没收藏的删掉，全收藏了就删最旧的。按名称去重：同名再记一次是更新营养值和分类。
  - `fav[]`（常吃，v8）：收藏的食物 id。内置食物存基准 id（`rice`，不带 `@`），自定义食物存 `my-…` id。新收藏在最前，不重复；指向已删除食物的 id 显示时跳过，不自动清理。
  - `combos[]`（组合，v8）：`{id:"cb-…", n, items:[{fid?, n, q, p, c, f, k?, s}]}`，最多 20 个，新的在最前。`items` 是存组合时从条目拷贝的快照（不含 `id`、`m`、`t`），之后改食物库不影响它。
- 每天：`state, entries[], water, lift, cardio, note, weight, waist, updatedAt`。
- 条目：`{id, fid?, n, q, p, c, f, k?, m(1–4), s, t?}`；营养值在记录时拷贝，`k` 存在时热量取 `k`。
  - `t`（v8，可选）：进食时间，当天 0 点起的分钟数（整数 0–1439）。没有这个字段表示不知道时间，读取时不要当成 0。
  - 自动写入的条件（`addFood(f,q,m,{live:true})`）：正在看今天，**并且**所选餐次不早于当前时段。餐次的时间顺序是 1 → 2 → 加餐(4) → 3（`ORD={1:0,2:1,4:2,3:3}`），条件是 `ORD[m] >= ORD[autoMeal()]`，这样晚上补记早餐不会被写成晚上的时间。合并进已有条目（同 fid、同餐次）时不改原来的 `t`。
  - 写 `t` 的入口：搜索结果份量按钮、最近 / 常吃 / 分类格子、组合、自定义表单、对冲页“吃了，记入”。不写的入口：参考餐单填入、整天复制前一天（复制时还会删掉原条目的 `t`）。
  - 用户改每餐时间时，这一餐所有条目的 `t` 设成同一个值；清空则全部删除。
  -`fid` 可能是内置食物的基准 id（`rice`）、份量变体 id（`rice@bowl`）或自定义食物 id（`my-…`）；判断“是不是某种食物”一律先过 `baseId()`。
- 状态键：`A` 训练日、`C` 休息日；旧数据另有 `B`（见第 8 节）。
- 备份：导出为 JSON。独立网页直接下载文件；Artifact 内不能下载，改为复制文本。恢复支持选文件或粘贴文本，二次确认后整体覆盖；原来有、备份里没有的日期会写成带新时间戳的空白日，这样云端的旧数据不会被拉回来。数据满 7 天且 14 天未导出时，人像按钮显示提醒点（云端同步时不提醒）。
- 迁移（`migrate`，加载、云端拉取、恢复备份后都会执行）：有旧数据但没有 `profile` 时，自动建立手动目标档案并保留三种状态，不弹引导。v8：`fav`、`combos` 不是数组时设为 `[]`，`fav` 去重；v8.1：`spread` 不是布尔值时设为 `true`；`my` 里 `cat` 不是五个合法分类的项（v7 及以前的“常吃”，`cat` 为 `"my"` 或缺失）用 `guessCat` 定分类、按分类重算 `s`，并把 id 加进 `fav`（它们原来都在“常吃”里）。可重复执行。
- 云端（仅 Artifact 内，附加能力）：`db` 能力，`data/users/<用户id>/`，按 `updatedAt` 新者覆盖。

### 食物库（`src/foods.js`，v7）

导出 `{FOODS, GROUPS, TAGS, CATS}`，只有数据。共 184 种，营养值都是按常见份量估算的。每种食物：

```
{ id:"rice",            // 小写字母数字，唯一。v6 的 30 个旧 id 不能改，p/c/f 也不能改
  cat:"carb",           // 营养分类 pro / carb / veg / fat / sweet，决定出现在哪个分类标签；sweet 的条目记录时 s=1、出现在对冲页
  g:"home",             // 场景分组 home 家常 / west 西式轻食 / out 外卖外食 / snack 零食饮品 / sweet 甜点，搜索结果里的小标签
                        // cat 为 sweet 时只能是 sweet（甜点）或 snack（饮品零食），见下方“甜点分类的分组”
  n:"米饭/杂粮饭",       // 纯名称，不含份量
  a:["白饭","大米饭"],   // 别名，可为空
  py:"mfzlf",           // 名称里每个汉字的拼音首字母 + 英文字母，全小写；长度必须等于汉字数 + 字母数（测试会查）
  u:[{k:"fist",l:"1 拳",x:1},{k:"bowl",l:"1 碗",x:1.5},{k:"g100",l:"100g",x:0.87}],
                        // 份量。第一个是基准（x 必须为 1）；k 小写字母数字，同一食物内唯一
  p:3, c:33, f:0.5,     // 基准份量的蛋白 / 碳水 / 脂肪（g），保留到 0.5
  k:…,                  // 可选：基准份量热量。外卖外食、含酒精饮品必填；与 4p+4c+9f 相差不超过 15%（含酒精的除外）
  top:1,                // 可选：出现在分类标签的默认格子里（v8.2 起每个 cat 10–12 个，见下方“默认格子”）
  hide:1,               // 可选（v8.2）：只为兼容旧记录而保留，不进搜索结果和默认格子；不能和 top 同时出现
  tags:["gluten"] }
```

- **显示名** = `n + " " + u[0].l`（如“米饭/杂粮饭 1 拳”）。旧食物拆分后拼回去与 v6 的显示名完全一致。
- **份量变体 id** = `<基准 id>@<份量 k>`（如 `rice@bowl`）。变体的显示名 = `n + " " + l`，p/c/f/k 乘以 `x` 后保留 1 位小数；基准没有 `k` 的，变体也没有 `k`。
- **TAGS**（饮食标签，本版只标注、不过滤，留给“饮食偏好”批次）：`meat` 任何畜禽肉（不含鱼和海鲜）、`pork` 猪肉、`beef` 牛肉、`poultry` 禽肉、`fish` 鱼、`seafood` 虾蟹贝等海鲜、`egg` 蛋、`dairy` 奶制品、`whey` 乳清蛋白、`soy` 大豆制品、`gluten` 含麸质、`nut` 坚果和花生、`alcohol` 含酒精。带 `pork / beef / poultry` 的必须同时带 `meat`。
- 加食物时：先定 id 和基准份量，写 py，填 tags；外卖必须带 `k`；跑测试会检查以上所有规则。
- **默认格子 `top`（v8.2）**：按大众常吃挑选，每个分类 10–12 个（蛋白质 12、主食 12、蔬果 11、油脂 10、甜点 12），名单由测试写死。个人口味的食物（法棍、Flan、可颂等）不放默认格子，靠搜索和“最近”找到。页面按 `FOODS` 的数组顺序显示格子；foods.js 每个场景分段里，带 `top` 的条目排在最前面，顺序就是显示顺序。
- **甜点分类的分组（v8.2）**：`cat==="sweet"` 的条目，`g` 只能是 `sweet`（甜点，18 种）或 `snack`（饮品零食，14 种，含奶茶 `tea`、含糖饮品、酒、薯片、巧克力、饼干）。不另设字段，对冲页按这个 `g` 分组显示（批次 2B.1 实现）。两组记录时都是 `s=1`，都可以对冲。自定义食物没有 `g`。
- **隐藏条目 `hide`（v8.2）**：值为 `1`，表示这条只为兼容旧记录而保留。`FBY[id]`、`FOODS`、`portionsOf(id)` 照常可用，历史条目和“最近”不受影响；`searchFoods` 不返回它，它也不能有 `top`。目前只有 `bag2`（法棍 半根）：法棍统一用 `bag3`，份量是 1/3 根（基准）/ 半根（`bag3@half`）/ 1 根（`bag3@one`）。页面上直接遍历 `FOODS` 的地方今后都应加 `!f.hide`。

### 引擎里的食物表和查找函数（`src/engine.js`，供批次 2B 调用）

- `FOODS`：只含基准份量，`{id, cat, n:显示名, p, c, f, k?, top?, hide?, g, tags, base:foods.js 里的原始对象}`。包含 `hide` 的条目，不过滤。
- `FBY[id]`：基准对象（就是 `FOODS` 里的那个）加上全部变体；变体形状 `{id:"rice@bowl", cat, n, p, c, f, k?, g, tags, baseOf:"rice"}`。
- `baseId(fid)`：去掉 `@` 之后的部分；`undefined` 返回 `""`。
- `portionsOf(id)`：某个基准 id 的全部份量（FBY 对象数组，基准在前）；id 不存在或传入变体 id 时返回 `[]`。
- `guessCat(f)`：给自定义食物猜分类。`s` 为真 → `sweet`；三大营养素都为 0 → `carb`；蛋白热量占比 ≥ 40% → `pro`；脂肪热量占比 ≥ 50% → `fat`；其余 `carb`。不会猜出 `veg`。
- `searchFoods(q, {my, fav, recent, limit=8})` → `[{food, score}]`。`q` 去空格转小写，空串返回 `[]`。候选是内置基准食物（跳过 `hide` 的内置条目，v8.2）和 `my`（自定义食物，只按名称，不受 `hide` 影响）。基础分取最高一项：名称相等 100、名称以 q 开头 80、别名相等 75、名称包含 60、别名包含 50；q 全是英文字母时，拼音首字母以 q 开头 45、包含 30（q 只有 1 个字母时只认开头）。自定义食物用名称里的英文字母当拼音首字母。加分：`recent`（`{fid: 次数}`，按 `baseId` 合并）每次 +3、最多 +15；在 `fav`（基准 id 或自定义 id 的数组）里 +8；自定义食物 +5。按分数降序，同分名称短的在前。`food` 对内置食物是 `FOODS` 里的对象，对自定义食物是传入的原对象。
- `recentFoods(days, todayStr, n=8)` → 快照数组 `{id, n, p, c, f, k?, s, cat:"recent"}`。统计 `todayStr` 之前 14 天（不含当天）的条目，按 `fid` 分组（没有 `fid` 的按名称，id 记为 `"rc-"+名称`），数值取每组最近一次的条目本身、不回查食物库，所以已删除的自定义食物也会出现。按出现次数降序、最近日期降序。

## 6. 工程结构与平台限制

- `src/foods.js`：食物库数据（见第 5 节“食物库”），没有逻辑。浏览器里是 `self.OnACutFoods`，Node 里是 `module.exports`。文件里不能出现 `</script>`。必须先于 engine.js 加载。
- `src/engine.js`：计算引擎，全部是纯函数和常量（`compute`、`pfError`、`buildTpl`、`advise`、`dayOk`、`totals`、`mealNote`、食物表与查找函数、超出摊平 `floorOf` / `cutCap` / `shiftT` / `carryOver`、日期工具），不碰 DOM 和存储。开头从 `OnACutFoods`（Node 下 `require("./foods.js")`）取数据，取不到就抛错。浏览器里是 `window.OnACutEngine`，Node 里是 `module.exports`。文件里不能出现 `</script>`。
- `src/on-a-cut.html`：页面主体（样式、存储与同步、视图、事件）。主脚本前有一行 `<!--ENGINE-->` 占位符，开头从 `OnACutEngine` 解构所需函数。
- `sh build.sh`（无参数）：把 foods.js 和 engine.js（foods 在前，同一个 `<script>`）内联到占位符处 → `dist/page.html`（发布 Artifact 用）；再套上外壳 → `index.html`（GitHub Pages 用）。两个产物都提交进仓库，都不手改。
- 测试：`node --test tests/`，提交前必须通过。`tests/engine.test.js` 覆盖 compute、pfError、日期运算、buildTpl、advise（示例 + 500 组随机输入的不变量），以及 searchFoods、recentFoods、portionsOf、guessCat、baseId；`tests/carry.test.js` 覆盖超出摊平（15 组，含 300 组随机历史的不变量）；`tests/foods.test.js` 校验食物库的结构、旧 id 与 v6 数值一致、份量变体、各分组数量。入口是 `tests/run-all.js`（`tests/package.json` 的 `main` 指向它，Node 22 靠这个找到测试）；新增测试文件要在 `run-all.js` 里登记，入口文件名不要带 `.test.`，否则会扫描目录的新版 Node 会把用例跑两遍。
- 写入 `settings` 或某一天的数据必须经过 `touch()`；营养值在记录时拷贝进条目。


- Artifact 内没有 `confirm/alert`、不能下载文件。
- “AI 估算”依赖 `sample` 能力，只在 Artifact 链接里可用；GitHub Pages 上搜不到时只有“手动填”。
- 食物库营养值均为估算值；计算结果是一般性健康建议，页面内有免责声明。
