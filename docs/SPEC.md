# On a Cut 刷脂助手 — 需求与功能说明

本文件是项目的唯一上下文来源。改功能前先读，改完后更新对应小节和文末的变更记录。

## 1. 使用者与目标

- 63.5 kg / 163.5 cm，30 天阶段性刷脂：减脂保肌、维持代谢。
- 每周 4 天晨练（约 40 分钟抗阻 + 40 分钟跑步机爬坡），3 天休息。
- 不要极端节食和纯水煮，要能融入日常、带弹性对冲机制。
- 只在手机上使用，单人使用。

## 2. 营养规则（应用内默认值，可在“准则 → 设置”修改）

| | 蛋白 g | 碳水 g | 脂肪 g | kcal |
| --- | --- | --- | --- | --- |
| 训练日（状态 A / B） | 100–110 | 165–180 | 42–48 | 1500–1600 |
| 休息日（状态 C） | 100–110 | 125–140 | 42–48 | 1350–1450 |

- 蛋白底线 85g，优先级高于断食窗口（关窗后仍低于底线 → 水冲 1 勺蛋白粉）。
- 每餐蛋白 25–40g；碳水集中在练后第一餐。
- 使用者问过“蛋白 1 g/kg + 碳水 2.5 g/kg”，结论是保持现方案（碳水周均相同，蛋白 1 g/kg 在缺口期不够保肌）。
- 进度用 7 日均重判断，目标每周 −0.3~0.6 kg；每周掉超过 0.7 kg 加 1 拳主食，连续 2 周持平减半拳或多走 2000 步。

### 三种状态

| 状态 | 场景 | 进食窗口 |
| --- | --- | --- |
| A | 11:00 左右练完，16+8 | 11:30–19:30 |
| B | 09:00 左右练完，14+10 | 09:30–19:30 |
| C | 休息日，主食少 1 拳 | 11:30–19:30 |

### 实物计量（回答和界面都必须用实物单位，不能只给克数）

- 瘦肉 / 虾 / 白身鱼：1 掌心（不含手指、厚 1.5cm，熟重 120–130g）≈ 30g 蛋白。
- 主食：1 拳（熟重 100–130g）≈ 33g 碳水。
- 法棍：1/3 根（80g）≈ 45g 碳水；半根 ≈ 70g 碳水。
- Bulk 蛋白粉：1 大勺 ≈ 23g 蛋白，牛奶另计。无糖豆浆粉：1 袋 ≈ 6g 蛋白。
- 燕麦默认一份 20g（使用者的固定习惯）。
- 蔬菜：两捧，少油不限量。烹调油：1 茶匙 5g。

### 甜点对冲

- 不批评，直接给当晚方案。
- 先保蛋白，再从主食和油里腾额度；额度用完则当晚主食归零（1 掌瘦肉或水冲 1 勺蛋白粉 + 两捧蔬菜）。
- 仍超出的部分：之后 2–5 天每天少半拳主食（约 −80 kcal/天）摊平，不加练。
- 练前担心低血糖：半根香蕉或 1 片吐司。

## 3. 界面原则（来自使用者反馈）

- 数字和卡片优先，文字越少越好；一眼能看到重点。大段说明放进“准则”页折叠。
- 一次点按完成记录；吃过的东西要能重复点选，不要每次重新输入或调用模型。
- 评价和建议要短，一行以内，直接说怎么做。

## 4. 功能模块

底部四个标签：今天 / 对冲 / 记录 / 准则。

### 今天（`viewToday`）
- 日期切换：可回看过去，可提前排未来 7 天（“明天”有专门标题）。
- 状态切换 A / B / C；进食窗口与倒计时。
- 四条卷尺式进度条：蛋白、碳水、脂肪、热量，带目标区间和蛋白底线刻度。
- 下一步提示（`nextHint`）：还差几掌肉、还能吃几拳主食、是否超额。
- 参考餐单（`TPL` / `tplCard`）：每种状态一份带时间的全天示例，可一键填入；当天已有记录时折叠。
- 记一口：先选餐次（第 1 餐 / 第 2 餐 / 第 3 餐 / 加餐练前），再点食物卡片记 1 份。类别：常吃、蛋白质、主食、蔬果、油脂、甜点。
- 自定义食物：
  - 输入一句描述（如“一个手掌大的章鱼”）点“估算”，由 Claude 估算蛋白 / 碳水 / 脂肪，数值可改。
  - 也可手动填；可只填包装上的热量（kcal）。热量留空时按 4·蛋白 + 4·碳水 + 9·脂肪自动算。
  - 记录后自动存入“常吃”类别（按名称去重，最多 60 个），之后直接点选，不再调用模型；“整理常吃”可删除。
- 今日记录：按餐次分组，每条可 ±半份；每餐一行评价（`mealNote`，纯规则，不调用模型）：蛋白不足 / 偏多、练后碳水偏少、晚餐主食偏多、油脂偏高、缺蔬菜、加餐偏多，都没有则显示“搭配均衡”。
- 喝水：250ml 一杯，目标 8 杯。

### 对冲（`viewHedge` / `hedgePlan`）
- 三列甜点卡片，点选即预演，可调份数；“吃了，记入今天”才写入记录。
- 结果用三张数字卡片：今晚主食几拳、蛋白几掌、蔬菜两捧；一行结论标签；三个剩余额度数字。
- 没有选择但当天已记甜点时，按实际摄入显示方案。

### 记录（`viewLog`）
- 本周训练 7 格 + 次数 / 4；抗阻、爬坡两个打卡按钮；训练笔记。
- 晨起体重、腰围；近 7 日均重、较起始、较上周；速度判断；体重趋势图（每日点 + 7 日均线）。
- 30 天打卡格：深色 = 蛋白达标且热量不超。

### 准则（`viewGuide`）
- 折叠的规则说明、额度表、计量表、调整规则。
- 设置：周期开始日、起始体重、每周默认状态、训练日 / 休息日额度。
- “复制 AI 交接档案”（规则 + 近 7 天记录）；导出 / 导入备份（JSON 文本）。

## 5. 数据与存储

- 本地：`localStorage["onacut.v1"]`，结构 `{settings, days}`。
- 云端（仅 Artifact 内）：`db` 能力，路径 `data/users/<用户id>/`，文档 `settings` 和每天一个 `YYYY-MM-DD`；按 `updatedAt` 新者覆盖；打开和回到前台时拉取。
- `settings`：`start, weight0, plan[7], win{A,B,C}, t{train,rest}{p,pf,c,f,k}, my[]`（常吃食物 `{id,n,p,c,f,k?}`）。
- 每天：`state, entries[], water, lift, cardio, note, weight, waist, updatedAt`。
- 记录条目：`{id, fid?, n, q, p, c, f, k?, m(餐次 1–4), s(是否甜点)}`；营养值在记录时拷贝进条目，之后改食物库不影响旧记录。
- `k` 存在时热量取 `k`，否则按三大营养素计算（`kcalOf`）。

## 6. 平台限制

- Artifact 内没有 `confirm/alert`、不能下载文件，所以备份用文本框复制粘贴。
- “估算”依赖 `sample` 能力，只在 Artifact 链接里可用，首次使用需要使用者允许，消耗其 Claude 用量；独立打开 `index.html` 时退回手动填写。
- 食物库和甜点的营养值都是估算值。
